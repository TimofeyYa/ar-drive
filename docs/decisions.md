# Архитектурные решения и открытые вопросы

> Этот документ — живой. Когда подтверждаются точные интерфейсы Cloud.ru AR или
> меняется решение по любому из пунктов, обновите запись и поставьте дату.

## Принятые решения

### ADR-001. Pure-Go SQLite вместо встроенной БД на CGO
**Дата:** 2026-05-17  
**Контекст:** ТЗ требует Docker-образы без сложных нативных зависимостей.  
**Решение:** Используем `modernc.org/sqlite` (pure-Go). Минус: ~20% медленнее
`mattn/go-sqlite3` на CPU-bound тестах, но для нашего write-light нагрузочного
профиля несущественно.

### ADR-002. Креды Cloud.ru передаются заголовками от SPA, не сохраняются на сервере
**Дата:** 2026-05-17  
**Контекст:** Нужен баланс между UX (не вводить ключи каждый раз) и безопасностью
(не хранить чужие секреты на нашем сервере).  
**Решение:** SPA хранит креды в localStorage зашифрованными (AES-GCM-256 +
PBKDF2). На каждый запрос шлёт заголовки `X-Cloudru-*`. Бэк держит только
in-memory кеш IAM-токенов (срок жизни 1 час).  
**Следствие:** При закрытии вкладки браузера серверный кеш токенов остаётся,
но без новых запросов не используется. Шер-ссылки требуют активной сессии
владельца — см. ADR-005.

### ADR-003. Эмуляция «пустых папок» через таблицу `folder_markers`
**Дата:** 2026-05-17  
**Контекст:** Generic-реестр Cloud.ru AR не поддерживает пустые папки и не имеет
явной операции удаления папки — папка существует как префикс пути файла.  
**Решение:** Хранить маркеры в SQLite и подмешивать их к листингу. При загрузке
первого файла внутрь — маркер удаляется. Удаление папки = итерация всех файлов
под префиксом + удаление по одному + сброс маркера.  
**Альтернатива:** Создавать «sentinel»-файл `.keep` — не принято, т.к. засоряет
реестр и потребует фильтрации в любых внешних скриптах.

### ADR-004. AES-GCM-256 + PBKDF2-SHA256 для localStorage
**Дата:** 2026-05-17  
**Контекст:** Нужно защитить ключи от других скриптов в браузере (на самом
localStorage защиты нет, но мы хотя бы не дадим простому `JSON.parse`).  
**Решение:** PBKDF2 (200 000 итераций) от парольной фразы или
`navigator.userAgent + случайная соль`. Шифрование AES-GCM с 12-байтным IV.

## Открытые вопросы

### Q-001. Точные пути file-эндпоинтов Cloud.ru AR
**Статус:** Открыт.  
**Контекст:** Публичная страница [api__artifact-registry](https://cloud.ru/docs/artifact-registry-evolution/ug/topics/api__artifact-registry?source-platform=Evolution)
описывает только registry-уровневые операции (list/create/get/delete/update
реестра). Пути push/pull/list/delete файлов внутри Generic-реестра — нет.  
**Решение проблемы:** В `internal/arclient/client.go` использованы наиболее
вероятные REST-конвенции:
```
GET    /v1/registries/{id}/generic/files?path=&pageSize=&pageToken=
PUT    /v1/registries/{id}/generic/files/{path}
GET    /v1/registries/{id}/generic/files/{path}
DELETE /v1/registries/{id}/generic/files/{path}
```
**Что нужно сделать:** Получить актуальный swagger из личного кабинета Cloud.ru
(или связаться с командой AR), сравнить и при необходимости заменить пути в
`arclient.Client`. Команда `make gen-openapi` зарезервирована под автогенерацию
через `oapi-codegen`.

### Q-002. Поддерживает ли AR presigned-URL для скачивания?
**Статус:** Открыт.  
**Если да:** Заменить серверный стриминг в `/s/{shortID}` на 302-редирект на
presigned-URL. Это снимает требование «активная сессия владельца» (ADR-005).  
**Если нет:** Оставить серверный стриминг и реализовать долгоживущий
server-side токен владельца (см. ниже).

### Q-003. Long-lived owner token для шер-ссылок
**Статус:** Открыт.  
**Контекст:** Сейчас публичная ручка `/s/{shortID}` требует, чтобы инициатор
скачивания прислал заголовки `X-Cloudru-*` (т.е. был владельцем). Это не подходит
для отправки ссылки коллеге.  
**Варианты:**
1. Если AR поддерживает presigned-URL — использовать его (Q-002).
2. Хранить refresh-token владельца на сервере под отдельным KMS-ключом.
3. Делать так, что при создании шер-ссылки клиент шлёт временно-валидный токен,
   а бэк его кеширует на TTL = max(`expires_at`, 7 дней). Истечёт — ссылка
   перестанет работать «как и задумано».

### Q-004. HMAC-подпись шер-ссылок
**Статус:** Запланировано.  
**Что:** Добавить `?sig=HMAC-SHA256(SHARE_LINK_SECRET, short_id|expires_at)` в
URL и проверять на ручке `/s/{shortID}` — защищает от перебора `short_id`.

### Q-005. Quotas / тарифы Cloud.ru AR
**Статус:** Открыт.  
**Что нужно:** Получить актуальные лимиты на throttling, размер репозитория,
кол-во запросов в секунду и зафиксировать в `docs/limits.md`. UI должен
отображать оставшуюся квоту.

### Q-006. Выбор Monaco vs CodeMirror в @snack-uikit/code-editor
**Статус:** По умолчанию — то, что использует `snack-uikit`. В MVP пока
используется простой `<pre>` для предпросмотра текстовых файлов — встроенный
редактор с подсветкой подключается отдельной задачей.

### Q-007. Распределённый rate-limit
**Статус:** Профиль `redis` в docker-compose готов, но `ulule/limiter` в коде
сконфигурирован под in-memory store. Для горизонтального масштабирования —
переключить на Redis-store.

### Q-008. Ротация audit_log
**Статус:** Открыт. SQLite-таблица будет расти неограниченно. Решение: 
nightly job + `DELETE FROM audit_log WHERE created_at < ?` + `VACUUM`.
